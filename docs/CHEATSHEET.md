# 🧾 Scrum — Key Objectives & Cheat Sheet

*The keep-forever, one-page reference. If you remember nothing else, remember this.*

## Key objectives (what this project proves I can do)

- Explain Scrum's empirical basis — **transparency, inspection, adaptation** — and why each event enforces it.
- Assign the three accountabilities correctly and know what each does **not** own.
- Estimate a backlog in **story points** and commit a sprint by **capacity/velocity**, not by wishlist.
- Read a **burndown** honestly — spot over-commitment, scope creep, and fake "done."
- Run each event for its real purpose and avoid the classic anti-patterns.

## The framework in one screen

| Pillar | Meaning |
|---|---|
| Transparency | Work + progress visible to all (board, burndown, DoD) |
| Inspection | Check progress toward the goal frequently (the events) |
| Adaptation | Adjust fast when off-track (re-plan, don't wait) |

**Values:** commitment · focus · openness · respect · courage.

## Accountabilities

| Role | Owns | Does NOT own |
|---|---|---|
| **Product Owner** | *What* + order (maximizes value); the Product Backlog | The estimate; the team's *how* |
| **Scrum Master** | The *process*; removes impediments; coaches | The work items; being a manager |
| **Developers** | The *how* + **the estimate**; build the Increment | Backlog priority |

## Artifacts → commitments

| Artifact | Commitment | In one line |
|---|---|---|
| Product Backlog | **Product Goal** | Ordered list of everything that might be built |
| Sprint Backlog | **Sprint Goal** | What we commit to this sprint + the plan |
| Increment | **Definition of Done** | A usable, *done*, shippable slice |

> **Done means done** — tested, integrated, shippable. Not "done except…".

## Events (timeboxes for a 2-week sprint)

| Event | Timebox | Purpose |
|---|---|---|
| **Sprint** | 1–4 wks | The container; a Sprint Goal; no changes that endanger it |
| **Sprint Planning** | ≤ 8h | Why (goal) · What (pull by capacity) · How (plan) |
| **Daily Scrum** | 15 min | Devs re-plan the next 24h toward the goal (not a status report) |
| **Sprint Review** | ≤ 4h | Inspect the Increment *with stakeholders*; adapt the backlog |
| **Sprint Retrospective** | ≤ 3h | Team inspects itself → **one concrete improvement** |

## Estimation & metrics

- **Story points** = relative size (complexity + effort + uncertainty), *not hours*.
- **Planning poker:** size privately → reveal → discuss outliers → re-vote.
- **Velocity** = points completed per sprint → commit near the average.
- **Burndown:** remaining points vs the ideal line.
  - Tracks the line → healthy.
  - Flat then last-day cliff → work wasn't really "done" until the end.
  - Line goes **up** → scope was added mid-sprint (**scope creep**).

## Anti-patterns (smells)

- Daily Scrum as a **status meeting** for a manager.
- **Changing scope** mid-sprint instead of routing it to the Product Backlog.
- A **retro with no action item** (theater).
- Estimates set by managers, not the Developers.
- "Done" that isn't shippable.

## 30-second self-check

1. Who owns estimates? → **Developers.**
2. Mid-sprint new story? → **Product Backlog**, PO re-orders for later.
3. Burndown trending up? → **scope creep.**
4. Retro output? → **one improvement you actually do next sprint.**
